#[derive(Debug, serde::Deserialize)]
struct SearchResponse {
    results: Vec<SearchResult>,

    id: String,
    title: String,
    #[serde(default)]

#[derive(Debug, serde::Deserialize)]
struct SearchResultSpace {
    key: String,                                  // NON-OPTIONAL — biggest fix risk for COMPAT-06

#[derive(Debug, serde::Deserialize, Default)]
struct SearchResultLinks {
    webui: Option<String>,
}

pub async fn handle_search(/* config + cql + limit + flags */) -> Result<(), AppError>;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ccli (local) → Confluence DC 9.2.13 | All response data is untrusted external input; serde must defensively parse. |
| User CLI input → CQL query string | User-supplied CQL is forwarded as a query parameter; no injection into a host-side query language because reqwest URL-encodes the value (PATTERNS.md "WR-05 injection protection" pattern at line 153). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-22 | Tampering | src/cli/page.rs SearchResultSpace.key parse | mitigate | The CASE B fix converts `key: String` to `#[serde(default)] key: Option<String>`. This eliminates the only non-Optional field across all 6 audit areas, removing a known parse-failure vector. |
| T-05-23 | Denial of Service | Excessive CQL limit | mitigate | Server-side hard-cap at 50 (Pitfall 6) protects against client-driven amplification. Existing default of 25 in handle_search is well below the cap. |
| T-05-24 | Injection | CQL query string | mitigate | reqwest's `.query(&[("cql", user_input)])` URL-encodes the value (PATTERNS.md lines 154-167 query-builder pattern). User cannot break out of the CQL parameter into other URL components. CQL itself is server-evaluated; ccli does not parse or transform it. |
| T-05-25 | Information Disclosure | Search results leak page titles for pages user does not have read access to | accept | Confluence DC enforces read-permission filtering server-side; ccli displays only what the server returns. No client-side bypass. |
</threat_model>
