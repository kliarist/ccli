The api functions are called with `ContentType::BlogPost` instead of `ContentType::Page`:
```rust
list_all_pages(&client, space_key, ContentType::BlogPost)  // hits /rest/api/content?type=blogpost
get_page_detail(&client, blog_post_id)                      // hits /rest/api/content/{id} (same endpoint, content-type discriminator in response)
create_page(&client, space_key, title, body_storage, None, ContentType::BlogPost)  // POST with type=blogpost
update_page(&client, post_id, title, body_storage, current_version, ContentType::BlogPost)  // PUT with type=blogpost
```

Notable difference vs pages: blog posts do NOT have a parent_id (ancestors), so create_page is called with `parent_id: None` and the `ancestors` field is omitted from the request body.

httpmock test pattern: same as plans 01 and 02. To distinguish from page tests, the new test mock must constrain `query_param("type", "blogpost")`.
</interfaces>
