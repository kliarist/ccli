## Widget Hierarchy: Comments Browse View

### Title Block (Comments Browse)

`Block::default()`
- `Borders::BOTTOM` only
- `BorderType::Plain`
- Left title: `"Comments — {PAGE-ID}"` — `Modifier::BOLD`
- Right subtitle: `"{N} total"` (no filter in v1) or `"Loading…"` — `Modifier::DIM`

### List Pane Block (Comments Browse)

Same widget rules as PagesBrowse List Pane:
- `Borders::RIGHT`, `BorderType::Plain`
- Inner padding: `Padding::horizontal(1)`
- `HighlightSpacing::Always` — reserve 2-char gutter to prevent layout shift
- Selected item style: `Style::default().bg(Color::Cyan).fg(Color::Black).add_modifier(Modifier::BOLD)`
- Highlight symbol: `"> "`

List item format: `"{author} · {date} · {first_line}"` — all on one line, truncated with `"…"` to pane inner width. (D-50)

- `{date}` format: `YYYY-MM-DD` (ISO date only, no time component — extract from version.when)
- `{first_line}`: the first line of `strip_storage_xml(body)`, truncated to fill the remaining width after author and date

### Preview Pane Block (Comments Browse)

`Block::default()`
- `Borders::NONE`
- Inner padding: `Padding::new(1, 1, 0, 0)`

Content: two metadata fields followed by a blank separator row, then the full stripped comment body.

Preview field layout:

```
Author:        {author or "—"}
Date:          {date or "—"}

{stripped comment body — full plain text via strip_storage_xml()}
```

Field labels: `Style::default().add_modifier(Modifier::BOLD)`
Field values: `Style::default()`
Missing value fallback (`—`): `Style::default().fg(Color::DarkGray).add_modifier(Modifier::DIM)`
Label column padding: 14 chars (`"{:<14}"`) — same rule as PagesBrowse.

Body text separator: one blank `Line::from("")` between metadata block and body text.

Body text: `strip_storage_xml()` output, rendered via `Paragraph::new(text).wrap(Wrap { trim: true })`. No body line cap (comments are shorter than pages; 200-line cap not needed, but apply it defensively via same 200-line rule if desired).

## Screen Stack Contract (Phase 4 Extension)

Extends the Phase 3 screen stack with a new `CommentsBrowse` variant (D-48):

```rust
enum Screen {
    SpacesBrowse,
    PagesBrowse { space_key: String, content_type: ContentType, state: Box<PagesBrowseState> },
    CommentsBrowse { page_id: String, state: Box<CommentsBrowseState> },
}
```

Stack operations (additions):

- `c` on a selected page in `PagesBrowse` (Browse state, filter closed) → push `CommentsBrowse { page_id }` (D-49)
- `Esc` on `CommentsBrowse` with no overlay → pop stack → return to `PagesBrowse` (D-48)
- `q` from `CommentsBrowse` → quit TUI (D-12 inherited)
- `o` on a selected comment → open comment URL in browser if `_links.webui` is available (otherwise no-op)

`CommentsBrowseState` owns: comment list, list state, preview cache, browse state (Loading/Browse), error, status message. Same pattern as `PagesBrowseState`. Filter state is NOT included in v1 (deferred).

## Fetch Contract (CommentsBrowse)

### Initial Comment List Fetch

- Trigger: on `CommentsBrowse` screen push
- Endpoint: `GET /rest/api/content/{id}/child/comment?expand=body.storage,version&limit=50`
- No pagination walk needed in v1 (limit 50 is sufficient for most pages)
- Show spinner in status bar during fetch
- On complete: display list in insertion order (API response order), transition to Browse
- On error: display error in status bar

### Preview Detail

Comment bodies are fetched inline in the list call (using `expand=body.storage`), so no secondary debounce-fetch is needed. Preview renders immediately from the fetched comment body.

Render: `strip_storage_xml(body.storage.value)` — identical to D-50/D-42 contract.

## CLI Output Contract

### `ccli page search "<CQL>"`

Always outputs a table — no TUI, regardless of TTY state. (D-45)

Output columns (in order):

| Column | Source | Width |
|--------|--------|-------|
| Title | `title` | auto |
| ID | `id` | auto |
| Space | `space.key` | auto |
| URL | `_links.webui` (resolved with base_url) | auto |

Default limit: 25 results. `--limit N` flag available to override. (D-46)
CQL expression: positional argument. (D-47)

OutputFormatter: use existing `OutputFormatter::print()` — TTY auto-detect applies (table on TTY, TSV when piped). `--plain`, `--no-headers`, `--columns` flags apply.

Empty result: print table with headers and zero data rows. No special empty-state message in the table output.

### `ccli attachment list <PAGE-ID>`

Output columns (in order):

| Column | Source | Width |
|--------|--------|-------|
| Filename | `title` | auto |
| Size | `extensions.fileSize` (human-readable: KB/MB) | auto |
| Media Type | `metadata.mediaType` | auto |
| Date | `version.when` (YYYY-MM-DD) | auto |

OutputFormatter: use existing `OutputFormatter::print()`. `--plain`, `--no-headers`, `--columns` flags apply. (D-56)

Human-readable file size formatting: 1024-byte boundary — values under 1024 B shown as `{N} B`; 1024–1048575 shown as `{N} KB`; 1048576+ shown as `{N} MB`. Round to nearest integer.

### `ccli attachment get <PAGE-ID> <FILENAME>`

No table output. On success: print single line to stdout:

```
Downloaded: {filename} → {destination_path}
```

- `{destination_path}` is `./FILENAME` (CWD) by default; `--output <path>` overrides. (D-54)
- On error: print to stderr in standard `{command}: error: {message}` format.

### `ccli attachment add <PAGE-ID> <FILE-PATH>`

No table output. On success: print single line to stdout:

```
Uploaded: {filename} ({human_size}) → page {PAGE-ID}
```

- MIME type auto-detected from file extension via `mime_guess`; fallback `application/octet-stream`. (D-55)
- On error: print to stderr.

### `ccli comment add <PAGE-ID>`

No table output. Workflow:
1. Launch `$EDITOR` with an empty temp file (D-53).
2. `$EDITOR` resolution: `$EDITOR` → `$VISUAL` → `vi` fallback (same as D-41).
3. On save and exit: wrap plain-text paragraphs (blank-line-separated) into `<p>...</p>` blocks and POST. (D-51, D-52)
4. On success: print single line to stdout:

```
Comment added to page {PAGE-ID}.
```

5. On error: print to stderr.

## Plain-Text to Storage XML Wrapping Contract (D-51, D-52)

Used by `ccli comment add` to convert the editor's plain-text output to Confluence storage XML before POSTing.

Rules:

1. Split input on blank lines (one or more `\n\n` sequences).
2. Each non-empty paragraph → `<p>{paragraph_text}</p>`.
3. Empty paragraphs (blank lines only) → skip.
4. Single-paragraph input (no blank lines) → single `<p>...</p>` block.
5. Escape `<`, `>`, `&` as `&lt;`, `&gt;`, `&amp;` in all paragraph text.
6. The resulting XML string is the `body.storage.value` for the POST payload.

Example:

```
Input (from $EDITOR):
This is paragraph one.

This is paragraph two.

Output (XML):
<p>This is paragraph one.</p><p>This is paragraph two.</p>
```
