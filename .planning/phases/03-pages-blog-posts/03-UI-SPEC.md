## Widget Hierarchy

### Title Block (Pages Browse)

`Block::default()`
- `Borders::BOTTOM` only
- `BorderType::Plain`
- Left title: `"Pages — {SPACE-KEY}"` — `Modifier::BOLD`
- Right subtitle: `"{N} total"` or `"{N} total / {M} shown"` (filter active) or `"Loading…"` — `Modifier::DIM`

For Blog Posts view: left title is `"Blog Posts — {SPACE-KEY}"`.

### List Pane Block (Pages / Blog Posts)

Same widget rules as Phase 2 List Pane Block:
- `Borders::RIGHT`, `BorderType::Plain`
- Active filter border: `Style::default().fg(Color::Cyan)`
- Inner padding: `Padding::horizontal(1)`
- `HighlightSpacing::Always` — reserve 2-char gutter to prevent layout shift
- Selected item style: `Style::default().bg(Color::Cyan).fg(Color::Black).add_modifier(Modifier::BOLD)`
- Highlight symbol: `"> "`

List item format: `"{title}"` — title only, left-aligned, truncated with `"…"` if it would overflow the pane width (D-44). No key/ID column in the list pane — those appear in the preview pane.

### Preview Pane Block (Pages / Blog Posts)

`Block::default()`
- `Borders::NONE`
- Inner padding: `Padding::new(1, 1, 0, 0)`

Content: metadata fields followed by a blank separator row, then the stripped body text (D-42, D-43).

Preview field layout (rendered as a `Text` with styled `Line` spans):

```
Title:         {title}
Author:        {author or "—"}
Version:       {version.number}
Last Modified: {version.when or "—"}
Parent:        {ancestors[last].title or "—"}

{stripped body — paragraphs as text, headings as UPPERCASE lines}
```

Field labels: `Style::default().add_modifier(Modifier::BOLD)`
Field values: `Style::default()`
Missing value fallback (`—`): `Style::default().fg(Color::DarkGray).add_modifier(Modifier::DIM)`
Label column padding: 14 chars (`"{:<14}"`) — identical alignment rule to Phase 2.

Body text separator: one blank `Line::from("")` between the metadata block and the body text.

Body text rendering (from `strip_storage_xml()`):
- Paragraph text: `Style::default()`
- Headings: raw text UPPERCASED, `Style::default()` (no modifier — uppercasing conveys heading role)
- Code block content: prefixed with 2-space indent, `Style::default()`
- Maximum preview body length: 200 lines (truncated with `"…"` at the end if body exceeds this)

`Paragraph::new(content).wrap(Wrap { trim: true })` — same wrap setting as Phase 2 preview.

## Screen Stack Contract

Phase 3 introduces a `Vec<Screen>` navigation stack in `App` (D-31).

```rust
enum Screen {
    SpacesBrowse,
    PagesBrowse { space_key: String, content_type: ContentType },
}

enum ContentType {
    Page,
    BlogPost,
}
```

Stack operations:
- `Enter` on a space in `SpacesBrowse` → push `PagesBrowse { space_key, content_type: ContentType::Page }`
- `Esc` on `PagesBrowse` (with no overlay open) → pop stack → return to `SpacesBrowse`
- `q` at any screen → quit TUI (D-12)

Each `Screen` variant owns its own independent `AppState` (Loading / Browse / Filter / Modal), list state, filter query, and preview cache. Transitioning between screens preserves their individual states — navigating back to `SpacesBrowse` restores the previously selected space and scroll position.

## Editor Suspend/Restore Contract (D-41)

When `e` is pressed on a selected page:

1. Set status bar to `"Opening editor…"` and redraw once.
2. Call `disable_raw_mode()`.
3. Execute `crossterm::execute!(stdout, LeaveAlternateScreen)` to suspend TUI.
4. Fetch current page body: `GET /rest/api/content/{ID}?expand=body.storage,version`.
5. Write XML to `/tmp/ccli-edit-{PAGE-ID}.xml`.
6. Launch: `std::process::Command::new($EDITOR).arg(path).status()`.
7. On editor exit: read the file content.
8. PUT to Confluence: `PUT /rest/api/content/{ID}` with incremented `version.number`.
9. Re-enter alternate screen: `crossterm::execute!(stdout, EnterAlternateScreen)`.
10. Call `enable_raw_mode()`.
11. Redraw full TUI state with status bar result:
    - Success: `" Saved."` in `Color::Green`
    - Conflict (HTTP 409): `" Conflict: page updated by someone else. Edits at /tmp/ccli-edit-{ID}.xml — merge manually."` in `Color::Red` — temp file is NOT deleted (D-39)
    - Other error: `" Error saving: {message}"` in `Color::Red`

The temp file path `/tmp/ccli-edit-{PAGE-ID}.xml` is shown verbatim in the conflict message (D-39).

`$EDITOR` resolution order: `$EDITOR` env var → `$VISUAL` env var → `vi` fallback.

## Fetch & Debounce Contract (Pages)

### Initial Page List Fetch

- Trigger: on `PagesBrowse` screen push
- Walk all pages of `GET /rest/api/content?spaceKey={KEY}&type=page&limit=50&expand=version,ancestors` until exhausted (D-33, CONTEXT.md Claude's discretion)
- Show spinner during walk
- On complete: sort by `title` ascending, transition to Browse
- On error: display error in status bar

For Blog Posts view: same pattern with `type=blogpost` filter (D-37).

### Preview Detail Fetch (D-43)

- Trigger: highlight settles on a new page after 150ms debounce (same D-19 pattern)
- Endpoint: `GET /rest/api/content/{ID}?expand=body.storage,version,ancestors`
- Result: cache in `HashMap<PageId, PageDetail>`, keyed by page ID
- While pending: preview pane shows previous content (no spinner in preview pane)
- On complete: run `strip_storage_xml()`, render paragraphs and UPPERCASE headings
- On error: preview pane shows `"Could not load content: {message}"` in `Color::Red`
- Cache hit: skip fetch, render immediately

## `strip_storage_xml()` Contract

Shared function used by both the TUI preview pane and `ccli page view` stdout output (D-42, D-36).

Module location: `src/output/xml.rs`

Signature: `pub fn strip_storage_xml(xml: &str) -> String`

Transformation rules:
- `<h1>` through `<h6>` content → uppercased text line, followed by blank line
- `<p>` content → text line, followed by blank line
- `<code>` / `<pre>` content → lines prefixed with `"  "` (2-space indent)
- `<li>` content → prefixed with `"- "`
- All other tags → stripped, inner text retained
- HTML entities (`&amp;`, `&lt;`, `&gt;`, `&quot;`) → decoded to their character equivalents
- Consecutive blank lines → collapsed to one blank line

## Module Layout Contract

New files introduced in Phase 3:

```
src/
├── api/
│   └── page.rs              — list_all_pages(space_key, content_type), get_page_detail(id),
│                               create_page(...), update_page(id, version, body)
├── cli/
│   ├── page.rs              — ccli page {list,view,create,edit} handlers
│   └── blog.rs              — ccli blog {list,view,create,edit} handlers (mirrors page.rs)
├── tui/
│   ├── app.rs               — EXTENDED: Vec<Screen> stack, Screen enum, ContentType enum
│   └── screens/
│       └── pages.rs         — render_pages(f, app, area) — all widget drawing for Pages/Blog Posts
└── output/
    └── xml.rs               — strip_storage_xml(xml: &str) -> String (shared by TUI + CLI)
```

The `render_pages` function signature: `pub fn render_pages(f: &mut Frame, screen: &mut PagesBrowseState, area: Rect)` — pure render, no I/O, mirrors the `render_spaces` pattern from Phase 2.

`PagesBrowseState` is a new struct (or enum variant payload) that owns the page list, filter state, list state, and preview cache for a single `PagesBrowse` screen. This keeps `App` as the stack manager and `PagesBrowseState` as the per-screen state.
